# 策略修正：不走本机编译，改走 CANNLab 云端环境

## 结论

**A1（本机装 CANN 9.0.0 编译环境）降级，不再作为主线。** 原因不是做不到，而是**性价比与目标不一致**：

- 本机编译**只能验证"编得过"，不能验证"跑得通"**——没有 NPU，`aclrtSetDevice` 那一步过不去。
- 而 CANNLab 是华为官方给算子开发的**云端 WebIDE**，**带 NPU**，能编译、能跑、能调、能出性能数据。
- 本机路线要翻两道墙：CANN 官方 OBS 全 403、hiascend 下载页有许可门槛、PyPI 包是假包；而云端环境这些都不存在。

## CANNLab 能力（据教程与官方说明）

云端 WebIDE，算子开发全流程：

- 创建算子工程（标准自定义算子 / **算子直调工程** ← 与本题 `npu_kernel_dev` 模板同形 / pyasc 算子工程）
- 代码编写 → 编译 → 部署 → 运行测试
- **NPU 调试 / CPU 调试**
- msSanitizer 异常检测
- 性能优化：**上板分析**与**仿真分析**

入口：`https://hidevlab.huawei.com`（实测 200，SPA 需登录后渲染）

## 资源池规则（用户提供 + 赛事页）

| 池 | 获取条件 |
|---|---|
| **CANNLab 公共资源池** | 开发与调试**优先使用**，无需已有成绩 |
| **竞赛专属资源池** | 已在 CANNJudge **提交作品并获得评测分数** 后可申请；**仅队长可申请**，申请后不可更换队名/成员，仅队长账号可登录 |

⇒ **"做一个跑得通的玩具 → 换到专属算力"这条路径是成立的**，而且比本机方案更短。

## 修正后的执行顺序

1. **登录 CANNLab / HiDevLab**（需用户本人账号，agent 不代登录）。
2. 在其中创建**算子直调工程**，把组委会的 `CMakeLists.txt` 契约与 `kernel.asc` 放进去。
3. **在云端编译 + 跑通组委会自带的极小用例**（`scripts/gen_data.py` 生成的 case0，`run.sh` + `verify_result.py`）。
   → 这一步**零提交消耗**，正是之前"盲交"问题的根治办法。
4. 先在云端把 kernel 编过、跑通、精度过。
5. **再**提交给 CANNJudge，取第一次真实分数。
6. 凭该成绩申请竞赛专属资源池，之后在专属池上做性能优化。
